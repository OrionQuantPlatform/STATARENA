# Five typed enrichment routes — pre-code contract

Exact scope: `/api/club-wikidata`, `/api/coach-portrait`, `/api/stadium`, `/api/player-honours`, `/api/club-links`. Only the new `dashboard/backend/services/orion-pro-enrichment.js`, new owned E2E and this namespace are written here. ROOT owns the actual app router, publisher, models/migrations and CI. No existing competition/archive/V1 proof is edited. Never fetch a provider, Neon or source body; no new storage or formula.

Without `v`, read the explicit sealed `analytics.catalog_publication` singleton. With `v=pro1...`, verify the exact retained published READY build token, then read its effective catalogue generation; this pins a catalogue view, not a sporting edition filter. Do not use global latest raw facts or wall clock to assert identity or tenure. A row and its provenance must be selected at that published CG. Dataset/document metadata and exact actor/foreign-key identity are typed, not parsed from stored source JSON. A miss is404 for unknown public identity,503 for unadmitted/ambiguous materialization; known player without collected honours retains the consumer's404 partial-career behavior. All errors are no-store. Invalid/duplicate/unknown params reject400 before SQL.

Enrichment evidence uses existing `ingest.source_datasets.contract_version='orion-enrichment-v1'` and same-source immutable record/document metadata bound to the effective catalogue snapshot. Source roles are exact registered codes `wikidata` and `uefa`, not provider display-name comparisons. Club Wiki lookup accepts either exact UEFA decimal identifier text (including leading zeros) or an exact normalized observed name/explicit alias plus the observed country code or exact selected typed country name. Unicode NFC and case folding preserve accents; no fuzzy/name-only/first-row fallback. Multiple qualified targets reject503. The Wikidata profile uses its own `wikidata_enrichment_v1` context and `source:exact` variant; it must not replace the V1 global profile. Return the observed founding year as a year string. A team having played at a venue does not prove that the venue is its home stadium. Model103 has no team→official-home-venue binding; `stadium`, `stadiumAlias`, and `stadiumId` stay unknown until typed provenance can prove them.

Club head coach comes from a same-source observed `head_coach` tenure and a typed identity. A current claim requires day precision, a known catalogue `knowledge_cutoff_at`, and both observed bounds with `valid_from<=cutDate<valid_to`; a NULL end in this model is unknown, not an open mandate. A competing plausible tenure makes coach ambiguous rather than choosing by recency or photo. Other known club facts remain usable. The coach portrait route resolves one exact normalized name with a same-source qualified coach QID. Multiple actors with the same name are ambiguous even if only one has a photo.

Photos use the exact `ingest.media_assets` link. Check image MIME, content-addressed key/hash, unique `legacy_asset_url`, and an allowed Commons alias that the real `safeImageUrl` maps to the already typed `/api/assets` route. The public DTO retains `photo.url`, author, license and real attribution URL; the browser uses the AWS redirect, not a provider fetch. Do not send a CDN URL as a legacy alias the consumer would reject. Asset metadata is mutable by model103; the ETag binds its current hash/key/MIME/alias/credit witness so old publication tokens do not validate stale asset metadata. E2E records actual307 without following it or claiming image byte delivery.

Stadium resolves exact `venue_source_ids` Wikidata QID and selected typed venue. Return capacity including0, observed capacity date, year-only opened value, and both known finite coordinates with documented ranges. A partial coordinate pair stays unknown for map display while known side facts may be retained separately. The model has no creation date or official-plan binding; neither is inferred from dates, unrelated matches, asset titles or embedded external URLs. `plans:null` and explicit unrecorded state differ from a known empty plan list.

Club links return `{links:{[club]:{entityId,clubName,countryCode,rankingName,method}}}` from the exact typed UEFA mapping in the same catalogue. `entityId` is `uefa:` plus the unchanged source identifier text; do not manufacture an original matching method or ranking name. A missing qualified mapping is unknown503, multiple distinct active mappings ambiguous503; a missing team alias is404.

Honours use exact actor alias, selected typed `football.player_honours` and exact honour definition at CG. Qualify only the explicitly scoped `orion-player-honours-v1` dataset `player-honours:<publicPlayerId>`, one bound source cohort and exact document actor record (`record_kind='honours_identity_v1'`, `external_key=<publicPlayerId>`). The persisted `outcome='winner'` is a winning observation; other outcomes do not become trophies. Retain typed team vs individual category and observed edition/season label; no arbitrary year parsed from an opaque edition key. Unknown label remains visible as an unlabelled observed edition count, not a fake year. Return existing `{available,honours,source,sourceUrl,fetchedAt}`; real `loadPlayerHonours`/`projectionGroups` perform their existing grouping/translation, no new scoring or career-completeness claim.

Attribution compatibility review before the first PG run: the legacy honours producer records `https://en.wikipedia.org/w/index.php?title=…&oldid=…#Honours` and source label `Wikipédia`. Preserve that exact closed query/anchor and the observed revision when it is a safe integer; reject unrecognized query fields, hosts or fragments. A plain article link is also accepted. Club and stadium include `sourceUrl` only when the admitted document records the matching QID in the Wikidata entity/wiki URL, and `fetchedAt` from its typed retrieval timestamp. An unrelated QID URL is never substituted. The original pre-code cases and missing-module receipt are retained; P04/P11/P14/P16 and the consumer replay were extended before the attribution correction, without a database run in between.

ETag binds route, all query params, published catalogue witness, exact selected row/provenance identifiers, and mutable media metadata used by the response. HEAD/304 only after metadata admission; no honours body serialization. A newer catalogue pointer can change a current witness even if an independent DTO is identical. Retained v stays byte stable across typed corrections; media metadata correction is the explicit exception described above. Bound candidate IDs (sentinel for ambiguity), 1000 honour observations, 2MiB response. Code does not change product limits to fit the fixture. Runtime SQL is ordinary read-only TLS with8s SQL/1s lock/5s idle limits. Inputs are closed and pinned; genuine source-free Node24 missing-entrypoint RED and executable E2E P00–P23 precede product. Owned PG requires a fresh ROOT release:600s/15000SQL/200HTTP/20kphysical rows/1GiB/96MiB/5connections/2workers. Stop on first unexpected failure and retain all proofs/cleanup; no cloud/source/RDS. Actual app integration stays separate from adapter HTTP.
