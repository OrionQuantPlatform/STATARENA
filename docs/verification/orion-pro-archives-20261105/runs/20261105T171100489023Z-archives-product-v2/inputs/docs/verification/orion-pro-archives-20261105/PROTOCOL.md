# Four typed archive routes — pre-code boundary

Exact scope: `/api/archives/index`, `/api/archives/season`, `/api/supplemental`, `/api/archive/matches/{match}`. Product ownership is the new `dashboard/backend/services/orion-pro-archives.js`; ROOT owns router integration, shared publication closure, migration and CI. The 103/107 models, migrations, frozen V1 readers, competitions adapter and all prior artifacts stay unchanged. No provider, Neon, cloud storage, source-body or legacy projection reads. No new storage, JSONB, resource or scoring formula.

Read the actual effective DG/CG of a READY build, sealed snapshots and publication pointer. Optional `v=pro1...` pins an exact retained build; an unpinned season/index reads a bounded set of current READY editions. Validate alias, season, ownership, original token and the intended archive cohort before GET/HEAD/304. Never reclassify every current league match as an archival observation. Unavailable/partial/ambiguous cohorts fail503 without cache. Unknown scope under a known ready archive is404; invalid/duplicate/unknown parameters are400 before SQL. A known, typed empty collection is only established by explicit coverage, not missing rows.

Archive admission for season results, goals and supplemental is a typed provenance contract using existing `ingest.source_datasets` and `dataset_snapshot_documents`. The respective dataset contract versions are `orion-archive-results-v1`, `orion-archive-goals-v1`, `orion-supplemental-v1`. Their dataset keys are `archive-results:<editionPublicCompetitionKey>:<seasonKey>`, `archive-goals:<editionPublicCompetitionKey>:<seasonKey>`, and `supplemental:<editionPublicCompetitionKey>:<seasonKey>`. The public key is the exact canonical `l_` alias when present, otherwise a validated exact typed slug. The resolved same-source immutable document set must be explicitly linked to the effective dataset snapshot. No URI is read from those records; they are provenance, not storage pointers. No freely supplied proof digest, body hash substituted for data, fuzzy-name matching or synthetic source registry.

Results and supplemental admit exactly one latest resolved `football.match_observation_details` row per selected published match and its physical revision, with a same-source record/document inside that edition's admitted document set. Select latest `recorded_from_gen<=DG` per actual source-record key, then require exact unique match membership; an unresolved, additional, missing or ambiguous admitted row cannot masquerade as a complete edition. Match cohort bijects with its READY summary. Plain typed fixtures can coexist without archive data, but do not enter these archive indexes. A raw correction after DG stays invisible until its new build, then historical v still reads the old document set and observation.

Results season DTO is `{season,source,competitions:[{id,name,country,matches}]}` for `archive.js` and `openfootball-history.js`. Results include declared unplayed rows, date notes, exact observed labels, typed date/round/stage and separate `ft/et/ht/p/final` scores, preserving NULL/absent/partial. Display fields may use their typed observation counterparts, never inferred from a raw date/time string. `sourceFields` exposes only exact recorded strings from the documented `match_observation_details` mapping (`Date`, `Venue`, `attendance`, `Comments`, `Team 1`, `Team 2`, `Round`, `Stage`, `Group`, `Season`, `competition`, `result`). Do not regenerate lexical score/neutral fields or synthesize unsupported legacy fields. Keep neutral boolean separate. Index fields count actual admitted tables/matches/results/unplayed/unverified dates; no path, fake checksum, fabricated source timestamp or claims of full original export parity.

Goals require a selected, same-source exact `events` coverage family for every match in that edition, backed by the admitted goals document set and full parent key `(match_id,source_id,feature_code,variant_key,recorded_from_gen)`. Present/empty is explicit; counts reconcile with physical members. Goal rows in this contract have registered typed `event_type='goal'`; no goal invented from a final score, no shootout converted into goals. `source_ordinal` then physical sequence orders the family; repeated legitimate occurrences are retained. Output the existing goal consumer shape `{date,match,minute,player,team,score}`. `match` is a display label formed from known typed home/away labels and final score, not a reconstructed source string. A nonempty goal family requires known date, sides and score for that display contract. Player label may come only from a selected same-source context at pinned CG, with ambiguity refused and unknown name explicit; no global unrelated profile. Source role, own goal, penalty and score NULL remain explicit. Zero observed events does not imply zero match goals. Goals-only editions are valid without claiming a result archive.

Supplemental preserves `{meta,competitions:[{folder,name,country_code,season,results,fixtures,goals}]}`; results and fixtures come from the same complete observed match cohort and typed status, with separate observed final scores. Goals use the exact supplemental `events` coverage and counts, not a guessed empty array. No payload body or public bucket path is stored/read. DTO uses real retained `date/home/away/round` labels; unknown result fields remain NULL. The unchanged `normalizeSupplementalCup` consumer is exercised on actual bodies.

Point archive uses exact admitted canonical `feature_code='match'` coverage (`present`, count1) and the exact resolved observation, record and document at the same READY pair. It returns `fixture`, `competition_id`, `competition_name`, `season` and the `endpoints` map used by `normalizeArchive` and `loadRemoteMatch`. Compose `match` and known `shots` from the frozen V1 SQL reader in-process at the exact pro1, with no HTTP fetch or fallback. Missing/unsupported sections carry explicit non200 statuses and states, even when a source collection existed but its full projection is unqualified. Do not manufacture a13-family complete legacy archive from 103 fields. Fixture/match and shots can be used; a full original source export remains a separate acceptance. Consumers must retain the same legacy extraction shape.

HEAD/304 only after admitted cohort metadata and bounded counts; same ETag/header as GET, no sporting payload reconstruction. Exact source/observation/coverage metadata and selected READY set determine archive version. SQL ordinary runtime only, TLS,8s SQL/1s locks/5s idle, no writes. Bound 2048 editions,10000 matches per representation,20000 goal rows,2MiB response, no successful truncation. Archive index and season omit source storage identifiers from the public body. Detailed dependency relation/keys are listed before code.
