# Release gate registered before the full load

A complete release requires a single stable publication generation, successful completed worker state, empty staging and application dirty queues, current source pins, public API parity and an attributed browser run on the release candidate. An HTTP 200 health response proves only that the first partition exists. A GitHub Actions success can be a time-sliced checkpoint. The November 4 partial production receipt recorded 147 requests, 267 checks, 9 failed checks and 26 unresolved selectors. Keep it as a failure baseline.

Failure modes include a pending or failed worker with zero queues, stale or missing object/profile receipts, absent orphan match scopes, a missing archive observation context, nonzero saved status lost in publication, changed source SHA after publication, new/superseded resources during the comparison, missing catalog editions, a paginated representation with missing/duplicated IDs, and a browser route showing a blank or fallback view. Each must produce a named failure or an explicitly unverified result. An expected source 404 has to identify the saved endpoint/params/status and corresponding published status; a missing typed row for an existing source 404 remains a failure. Runtime-only 404 and success counts cannot establish collection history.

Acceptance is read-only. Run after publication owner reports workflow completion, using a new receipts directory for every run. The metadata gate checks the worker and queues first and exits before the expensive comparisons if they are not complete. The following stages are separate: source universe and typed delivery, public HTTP contracts and genuine source parity, safety/error behavior, release-hosted browser behavior, and cutover authorization. During preparation only existing receipts and source code are inspected.

The catalog selection, match address mapping, 003–009 migration hashes, and curated script hashes must match the deployed worker commit. All DB reads use verify-full TLS, a read-only repeatable snapshot and bounded statements. A statement timeout, missing relation or incomplete audit results in a nonzero exit without widening the timeout on production. Full source pin validation lists structural mismatches and representative failed selectors, never raw bodies or credentials. Existing schema/publisher source of truth lives in relational_materialize.py, relational_match.py and relational_catalog_keys.py.
