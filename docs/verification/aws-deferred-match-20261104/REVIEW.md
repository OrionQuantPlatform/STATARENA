# Defer full-season reads on direct selected-match pages

The private patch applies cleanly to `d5df4c5a9a31ee7954dc9403f2fdccb8736371e9`. Its SHA-256 is `4c9510d038ff3be4d5d748b7fe48084afbee6b8e0de16525d4279147196e7d34`. Only four application files change: FootballContext.jsx, resources.js, PlayerDetails.jsx and MatchDetail.jsx. No route or API contract changes.

| Page feature | Data used | Proposed load trigger |
|---|---|---|
| Finished match overview | Manifest/season for header and navigation, client status, match summary with score, leaders and chart data | Fetch immediately; reuse a finished match from a completed scope when present |
| Full shots, lazy statistics, lineups and analysis tabs | Selected per-match endpoint; summary may already contain overview totals | Selecting the tab; the real shots tab had one match-shots request and zero partitions |
| Upcoming default context | Target teams’ scouting routes, relevant league partitions, and fixture histories | Default context is visible immediately. Montpellier–Metz requested three Ligue 2 partition pages plus three fixture pages |
| Standings | Competition from manifest, selected-season fixture pagination and an existing competition-specific season fallback if required | Selecting standings requested two Ligue 2 fixture pages and rendered the table |
| Player dialog, peer percentile/rank and performance comparison | Full appearance cohort, match data and competition metadata | Explicit performance/active comparison intent; keep the same match/client mounted, show cancellable busy modal, offer retry on failure |
| Global search | Competition catalogue plus full unfiltered players/clubs index and cup catalogues | Existing focus/pointer-enter intent; do not return an empty catalog-only scope from searchData |
| Bookmark, navigation, team links | Current match identity/name, manifest and local research storage | No season reads needed; bookmark toggled without a partition request |
| Settings and methodology | There is no standalone settings route in this checkout. MethodPage displays actual count of matches and appearances from f.data | Excluded from this patch; forcing metadata-only would report false zeros |

**13 recorded browser scenarios, all final expected outcomes satisfied.** Source data came from the real AWS origin; a bounded local HTTP cache replayed it to the actual private Next app and Chromium. On first load of Reims–Sochaux, deferred hydration reduced 7 partition calls to 0 and structured response bytes from **3,738,727 to 10,746** (99.7%). The original scoreboard appeared after 2.153 s, and representative private dev replays after 1.60–1.72 s. These are single development observations with a deliberately introduced 220 ms local partition delay, not end-user deployment latency. Image traffic is excluded from structured-byte counts.

Clicking Yaya Fofana loaded the original cohort exactly on intent (7 pages), restored the full appearance, and allowed a two-player comparison with Théo Leoni. A 503 produced a visible error and retry; Escape canceled the loading modal and the late request did not reopen it. A warm same-league list showed a real different match with no new season or match-summary request. Warm Serie A followed by a Ligue 2 match previously yielded a silent player click. The revised candidate fetched only Ligue 2 on that click and opened the correct player. A synthetic native season `2026` in the otherwise genuine 2026/2027 match reproduced an unavailable-season error; the guard checks the manifest's actual league/season membership, preferring a real native partition before its display label. The source has no genuine older edition for this match; the numeric season case is a single-field perturbation.

The initial match and focused player cohort are separate. Hydrating a player cannot replace the page dataset, recreate its client, unmount its tab, or turn a scoped comparison into a summary-only approximation. Resource errors remain retryable. Cache reuse requires actual selected-match membership. The unchanged existing dataset loader owns full season/league filtering on every other route. Resolution of legacy summary/archive/network failures still follows the existing rematerialized API fallback.
