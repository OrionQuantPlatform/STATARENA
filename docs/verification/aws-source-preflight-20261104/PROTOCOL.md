# Live catalog, profile and supporting source preflight

Before any product or model changes, enumerate the source universe used by the rematerializer on RDS. Use the runtime read-only role over verify-full TLS, enforce statement timeouts, and resolve only checked source versions. The audit must count every eligible catalog, profile and projection, validate all typed shapes where the indexed body or exact previously audited checksum exists, and report every missing or unverified source explicitly. Do not request external source objects. Send aggregate profile shapes or source-specific narrow profile envelopes, never the entire imported document table. Historical catalog SHA evidence counts only if the current path and digest match an independently validated complete file. A future change to the encoder or DDL requires a separate failing local workflow before implementation. Include exact command, numerical coverage, failures and output transfer in results.

Validate the claimed digest against compact sorted-key UTF-8 JSON and the immutable path basename, then validate each body with the existing profile model. Also count all staging references exhibiting this issue, including other endpoint families, without pulling their entire bodies. Record representative bounded cross-family samples separately. Before changing the rematerializer, run a disposable PostgreSQL 18 source-to-typed profile workflow. A valid logical reference must publish a typed profile. A wrong filename, wrong reference, unrelated namespace, or wrong indexed envelope must fail closed with no receipt. Physical hashes must still work. Real RDS input is read only.
