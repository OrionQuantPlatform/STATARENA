# Backend hosting acceptance, 2026-11-04
Before implementation: exercise a real loopback HTTP server that converts inbound requests to the documented Lambda Function URL v2 event, calls the adapter and converts its buffered result back into HTTP. Use a deterministic Web Request handler to isolate transport; the release gate separately exercises the real packaged application and actual AWS + RDS.
- Preserve the raw path, escaped/repeated query keys, GET/HEAD, conditional headers, ETag, HTTP status, Location, original binary/gzip bytes, explicit content length on HEAD, and empty 304.
- Reject unsafe paths before WHATWG URL normalization, unsupported methods before reaching app/DB, and invalid events. A raw absolute/network-path input must never switch hosts.
- A large compressible JSON response fitting after negotiated gzip succeeds; an incompressible oversized response fails explicitly without returning truncated content; never exceed Lambda's buffered envelope. No language fallback to files or provider APIs.
- Separate deploy validation: isolated artifact bucket, IAM-only origin with two scoped distribution permissions, VPC DB-only access, no database/restart/import resources, no external-origin providers, no secrets in output or arguments. Production must verify both ends, cache/conditional/CORS behavior and worst-case payloads; localhost cannot prove AWS behavior.

Run from repository root: `node infra/aws-backend/transport-e2e.mjs`. A local AWS emulator is not used. Expected scenarios and inputs appear in this document and the script. Actual evidence is in red.txt and transport.json; do not treat edition-specific fixture passes as production verification.
