# Exact independent dependency oracle contract

Suggested commit: `test: qualify typed publisher inputs and complete precode oracles`.

Scheme: orion-four-readers-dependencies-v1. Representation remains summary-v1-shots-v1. Hash input is canonical UTF-8 JSON with sorted object keys,compact separators and ensure_ascii=false. Values are explicitly tagged: null,bool,i64(decimal string),f64(float.hex),decimal(fixed decimal string),date(ISO),timestamp(UTC microseconds),array,object. Boolean is checked before integer; no lossy float/JavaScript conversion of bigints. Nonfinite floats are refused by this synthetic admission contract. Table rows are ordered by their canonical tagged bytes, not timestamps/IDs used to choose a sporting observation. Each table entry binds real PK identity plus SHA256 of the included typed columns.

At dg select the exact edition,all its selected nondeleted matches,participants,squad observations,engagements,scores,canonical coverage and the selected shot source/variant family. Noncanonical decoys are excluded. At cg select the referenced competition,team/player identities,matching public aliases and the unique winning same-source profile at provider_exact>normalized>manual rank. The oracle refuses ambiguous winning profiles and coverage. Required period/row-contract lookups,source records/documents/datasets/sources and actual upstream row policy/transform metadata are included. No *_current view is used.

The closure excludes global snapshot IDs/generations,dirty hints,publication pointers,transport observations and physical source storage/retention fields. It excludes mutable interval ends and updated_at; the selected real row PK/from-generation and all other included typed values still bind its immutable version. This keeps historical closure digests stable when a legitimate interval later closes, and keeps unrelated C stable when shared A/B source versions change. Build fields separately bind exact effective sealed dg/cg snapshot identities. Reusing an older pair requires independently proving its closure equals the requested pair; a merely smaller generation is insufficient.

Sealed historical closures are memoized by exact edition/dg/cg to stay within the existing SQL cap. The source-free controlled fixture's source-document/catalogue metadata stays unchanged after initial setup; sporting updates use close/insert generations. Every existing full94-table checkpoint also compares all non-output source-table digests against its last owner-controlled input epoch. Only a successfully committed fixture _generation advances that epoch. Any publisher source/dirty mutation therefore fails the checkpoint instead of being hidden by memoization. Historical interval ends/updated_at are deliberately excluded as above. No runtime API cache or production planner supplies this oracle.

Build code_content_sha256 must equal the actual single future product script's bytes; its code_commit in this local-only harness is explicitly local-owned-e2e-v1, not a claim about Git. Downstream transform_version=orion_pro_publish_v1 and metrics_contract_version=orion_pro_four_readers_v1. environment_sha256 binds the exact approved model,012,013,frozen reader,existing grant/schema/migrator code,PG180006 and digest scheme. Upstream source transform hashes remain their actual fixture values. Neither a matching SHA nor a local label admits real sources or remote publication. If the product path is absent, no build code hash is fabricated and no output oracle is called.

The initial owned-input exact pair is dg3/cg2. The future full workflow first commits/restores its deliberate negative input generations, so it captures the exact requested first-publication pair **before** starting the first publisher and asserts every initial build uses that declared pair; it does not pretend those later inputs are still dg3. For later affected editions, the oracle records the requested input closure and compares actual build snapshots/closure/code/contracts. Untouched editions must retain exact build,snapshot IDs,dg,cg,dependency digest,tokens,HTTP bytes/ETags/cursors. A's data correction affects A; shared team/player correction discovers A/B through actual old/new dependency membership; C-only score/profile/nullable-shot correction affects C. Both A3 absent/null successors affect A. No dirty hint alone chooses the dependency closure, and no publisher resolver is used to compute the independent oracle.
