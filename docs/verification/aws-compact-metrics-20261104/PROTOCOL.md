# Compact normalized metrics migration and publication

Preregistered before implementing 009. Use local disposable PostgreSQL 18 only. The two retained, immutable native COPY inputs contain all 221,906 published half-stat metrics and all 189,510 full-player metrics. Load these into the sealed old schema with genuine row addresses and valid parent keys, take a local read-only comparison snapshot, apply 009, and verify bidirectional EXCEPT ALL across all eleven native columns and all 411,416 rows. Include existing labels, metric keys, row positions, null/missing distinctions and fractional totals. Verify original derived heaps persist until both families pass, atomic migration rollback on an injected invalid input, and harmless migration replay. The source schema must remain untouched.

For new writes, retain identical application-level GET values, independent 404s/variants, partial update, retry, late dirty markers, concurrent transactions, and the accepted sixteen-match copy grouping. Stress dynamic unknown keys, aliased labels sharing a physical slot, oversized/fractional numbers outside narrow storage, explicit null vs absent and zero. Both the original and batch APIs must use the same transformation as SQL migration. Named scalar columns, normalized dictionaries, template membership and typed overflow only. No serialized response data in the compact tables. Verify compatibility views, indexes and byte/latency measurements, and record source/model/core phase durations without serializing bodies for timing. Avoid production writes or live DDL. Suggested commit `perf: compact normalized player metric storage`.

During migration backfill, readers must continue to see the complete old derived tables. Inject a local SHARE lock on a new compact destination, wait for the converter to block on its INSERT, and issue a real read of the old table under a 500 ms lock timeout. Concurrent writers on two distinct match IDs must both complete even if they introduce novel player/half templates in opposite order across calls within one transaction. Also force an unrepresentable legacy presence mask in the second family and verify that both original heaps survive a failed cutover. These acceptance cases were added after the preliminary implementation exposed lock contention and a real SQLSTATE 40P01 in the independent review.

Long source-defined labels and metric keys are unbounded text in 004. Exercise an incompressible label/key larger than a PostgreSQL B-tree tuple, plus a signed floating-point zero. Rendering and the old native row contract must survive.
