# Eight typed competition routes — pre-code E2E contract

Scope is exactly `/api/standings`, `/api/open-cups`, `/api/openligadb`, `/api/nations-results`, `/api/cup-index`, `/api/cup-table`, `/api/cup-snapshot`, `/api/matchdays`. Product ownership is the new `dashboard/backend/services/orion-pro-competitions.js`; ROOT owns router integration, schema, migration, publisher and CI. No existing product, model103, migration012–015, V1 reader, publisher, test or proof is edited in this lot.

Only immutable published typed103 facts at the actual READY build DG/CG are read. `v=pro1...` is optional for historical routes; without it, resolve a bounded current published edition. A supplied token is recomputed exactly, edition/season checked, then retained historical observations are selected at its DG/CG. Never use global latest facts, provider HTTP, Neon, legacy `statarena_app` projections or source bodies. Missing READY/cohort/identity is explicit503; an unknown competition under an otherwise ready catalogue is404. Invalid, duplicated or unknown query parameters reject400 before SQL. Unrelated paths return null. Every success is `competitions-v1`; readiness/cohort validation precedes conditional304.

The existing consumer modules are acceptance oracles: `cup-matches.js`, `knockout-bracket.js`, `competition-matchdays.js`, `nations-standings.js` and `cup-catalog.js`. The React consumers `CompetitionStandings`, `CupCompetition`, `NationsCompetition`, `NativeKnockoutBracket` and `MatchdaySchedule` define the required envelopes. Test real response bodies through these unchanged functions. This lot exposes typed public DTOs; it does not claim a byte-for-byte reconstruction of original OpenFootball/OpenLigaDB/SportScore source documents.

Standings retain observed rank, ties, nullable values, points and adjustments. Do not recalculate rank/points or invent a zero. `difference` is the existing goals-for minus goals-against display value only when both are known. Choose latest `data_revision` per the exact model103 snapshot context at `recorded_from_gen<=DG`, then the latest observed table per same source/stage/group/label/overall scope. More than one source for the edition or an indistinguishable tied observation is an unqualified cohort and returns503; no invented provider priority. Home/away tables do not silently replace overall. Missing snapshot is unknown503; a retained snapshot with zero rows is known empty. Source labels have priority over same-source catalogue profiles; missing names do not cause rows to disappear. Images use only qualified immutable media metadata and configured CDN origin.

Cup routes select every published edition match through the build's match summaries and verify complete membership against selected published matches at DG. Keep raw round labels/numbers, tie and leg facts; never infer them from scores or dates. Deterministic source order is stage sequence (NULL last), round number (NULL last), date/kickoff (unknown last), then numeric match identity. `matchdays.matches` is a map keyed by exact match alias; unknown rounds remain counted as unknown and are not fabricated. Playoff is emitted only when a declared stage type proves it. Date-only fixtures retain dates without invented UTC midnight. Score periods remain distinct: regulation, after extra time, shootout, half-time and final without shootout. NULL and absent score observations remain explicit, never0–0.

`open-cups` keeps `{matches,name,season,source}` with `team1/team2` and period score objects; `openligadb`/`nations-results` keep the normalized `{matches,season,source}` shape consumed today. Nations league/group values must be explicitly declared stage keys A–D and canonical group keys1–4 under this route contract; no name-based guessing. The Nations OpenLigaDB shape selects only declared League A, the results shape only B–D, matching the two existing consumers. A historical `finished` match with no recorded final score retains its actual status plus nullable score/state; unchanged OpenFootball consumer derives its display status from score availability and already excludes past unscored matches from upcoming. Record that existing UI behavior rather than pretending to reconstruct a missing score.

`cup-snapshot` dispatches `native`, `standings`, `open-cups`, `openligadb`, `nations-results` to the same typed cohort and envelope as the direct route. Native snapshot includes exact public match IDs/team IDs, dates/UTC only when known, score fields and declared rounds. `cup-table` returns results/fixtures row arrays compatible with `normalizeSupplementalCup`; results are retained finished/awarded observations, fixtures are other explicitly selected match states. `cup-index` returns typed cup/tournament/supercup catalogue entries, editions, exact row counts and native aliases. `kind=worker|supplemental` is a requested envelope category; it never authorizes a source fallback or merges identities by name. Omit storage paths and invented source timestamps/hashes. Slugs/aliases are exact; ambiguous aliases fail. Known empty index/edition is distinct from unavailable publication.
