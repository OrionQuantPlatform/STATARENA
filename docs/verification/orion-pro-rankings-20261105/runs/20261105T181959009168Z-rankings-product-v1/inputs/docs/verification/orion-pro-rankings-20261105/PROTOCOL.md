Scope is the four FIFA and UEFA HTTP forms `/api/rankings/index`, `/api/rankings/edition`, `/api/rankings/associations`, and `/api/rankings/club`. The new module reads existing model103 relations with the ordinary AWS runtime role. ROOT owns route wiring and the production publisher.

The current request resolves the explicit sealed catalogue pointer and requires a current published READY build with that same catalogue and representation. Optional `v` pins a retained published READY build and the exact V1 token, including its sealed catalogue. Neither request reads the latest raw generation. Invalid or duplicate parameters fail before SQL. The edition keys are real ISO calendar dates with the registered authority suffix, or a four digit UEFA ending year. Associations uses only the UEFA association edition for the requested year. Club history uses only official UEFA club editions.

Each admitted root has the registered source code, exact system code, authority, subject, gender, edition suffix, `rankings:<kind>` dataset and `orion-rankings-v1` contract. Select the highest revision per physical system and edition among exact root documents bound to the catalogue, with the observation at or before its CG. A newer unbound root does not replace a bound root. Two methods claiming the same public edition are ambiguous. A bound latest revision with `ranking_collection_complete` absent or false is pending. This existing quality boolean is a source admission attestation. The publisher must verify source cardinality independently before setting it. The reader also checks nonzero bounded typed row counts and, for each returned row, its exact identity and provenance. It cannot detect source rows omitted from both the attestation and the typed input.

Entries and annual components belong to the exact immutable ranking snapshot. The entry's source record supplies the provider external key and optional ordinal. Its document is bound to the effective catalogue and the native seal proves it is the root or declared ancestor. Join the exact provider identity at the observation generation, and select the canonical profile from the same source record in the scoped `ranking:<kind>:<edition>` context at that generation. Closed historical profiles remain available to their exact older observation. Mutable stable team or association names are never a fallback. Ties keep their ranks, with ordinal order in the same document and deterministic document/key ordering across documents. Numeric points stay exact JSON numbers and NULL stays NULL. Return the same normalized rank DTO field names. Expose only source URL metadata from a recognized public provider URL, and keep effective, published, updated and retrieved dates distinct.

The association consumer reads `sourceRow.seasonRankings`. The annual component period is the exact observed four digit `seasonYear`, `value` is observed `totalPoints` for this contract, and `national_association_points` is the separate native field. Seasonal counters remain seasonal. Model103 has no exact aggregate `overallRanking.numberOfTeamsStillInPlaying` field. Do not infer it from an annual component. The DTO carries the supported typed subset of the former source shape. It does not reconstruct the original provider object.

Club history resolves the published team alias and an exact, provenance-qualified UEFA source identifier. Keep leading zeros. A known club without a qualified mapping returns `rows:null`; a missing public actor returns404. Multiple active mappings return503. A selected, complete edition can have `row:null` for the club. An incomplete selected official edition fails the history request instead of presenting a false unranked row. A row for the wrong identity or provider key is not a match. The index lists admitted editions and reports the keys of incomplete or ambiguous editions separately, without a source object path or an invented original catalogue collection count.

The SportsAPI edition suffix remains a distinct source with `officialEdition:false`. It does not substitute for an official UEFA or FIFA edition. Model103 cannot represent legacy unranked rows or multiple original occurrences of one actor in the same snapshot. Such source editions remain unadmitted until there is an exact typed representation.

HEAD and conditional responses check the same typed publication and per-scope metadata before returning an ETag with zero body. Scoped body reads use the same snapshot witnesses. Bounds are 512 editions, 4096 entries per edition, 32768 annual components per response and 2 MiB response size. E2E runs the existing front-end consumers on unchanged captured HTTP bodies. The local release uses one owned PG and one Node24 HTTP service, ordinary read-only TLS, 8 s SQL, 1 s lock, 5 s idle and the established campaign bounds of 600 s, 15000 SQL, 200 HTTP, 20000 physical rows, 1 GiB PG disk, 96 MiB evidence, 5 connections and 2 workers. The first unexpected failure stops the run with a receipt and cleanup.
