# Complete fixture traversal regression

Before changing the consumers, drive the actual FootballDataClient and cupWorkerSnapshot functions against the application's Web Request handler over loopback HTTP using a fresh, real PostgreSQL schema. Insert 123 common fixtures plus one league-only and one day-only fixture, a native cup with an overlapping row and a preserved saved-only row, an empty scope, and a dense league of 210 rows. The first dense page fits; the second 100-row page exceeds the real 2MiB limit. Test all IDs/values, completed cursor traversal and zero results (no partial or duplicate rows). Induce a real generation change after page one using an independent SQL writer, then verify the initial rows are discarded and fresh scores win. A second generation conflict must leave only a complete saved cup or the existing failure/fallback state and may never publish a partial schedule. No production or provider requests. Preserve team/season fallback behavior, round names/playoff flags and zero scores. Source implementations may be unbounded or bounded before the change: record the measured baseline, not an assumed failure. Suggested commit `fix: traverse every fixture page for calendars and native cups`.

Run from repository root with Bun, installed dashboard dependencies, Python psycopg 3, and embedded-postgres 18.6.0-beta.19 at STATARENA_TEST_TOOLS (default /tmp/statarena-archive-remat-pg):

```sh
PYTHONPATH=/tmp/statarena-archive-remat-pg/python bun docs/verification/aws-fixture-pagination-20261104/run.mjs after
cd dashboard && STATARENA_FIXTURE_EVIDENCE=../docs/verification/aws-fixture-pagination-20261104/identity.json node scripts/verify_competition_fixtures.mjs
```

Actual baseline: the unbounded legacy routes returned all 124 narrow fixtures with one HTTP request, but the oversized league hit the 2MiB response limit and the calendar returned zero. There was no cursor use or generation restart. The corrected consumers use the existing /api/fixtures implementation. The date and league scopes returned 124 unique IDs each, including the correct scope-specific fixture. Native cup returned 125 unique fixtures, preserving the saved-only fixture/round and replacing a stale score with a fresh zero. A real 409 restarted the complete schedule; two 409s exposed only the original local fallback/error or the complete saved cup. The 210-fixture dense league hit 413 on its second page at limit 100, restarted at 50 and returned every row. Empty scope remained an empty successful result. All eight scenarios passed. The existing league/season identity check also passed over HTTP, and both changed consumer entry points bundled for browsers. See before.json, after.json (actual paths, bounds, status and final-page info), identity.json and browser-build.log. Validation used disposable local data and the application HTTP handler; deployment of the frontend and public UI acceptance remain separate release steps.
