# Paginated SQL and origin measurements

The dense 100-match page read 11.74 MB of PostgreSQL fields, including 8.79 MB for 4,788 appearances, to produce 1.97 MB of public JSON. The SQL took 279 ms on the production RDS server. Two independent private changes reduced work on those same rows. Caching field-name conversions cut the local handler median from 223 to 159 ms. Sending ordered appearance values cut PostgreSQL field bytes by 47%. The database schema and deployed application were unchanged.

## Private candidates

1. **Cache transformed column names on the application side.** For twelve matched pairs, the local replay passed the same in-memory PG row through the actual page handler with and without the isolated change to camelRow. Median helper time fell from 126.46 to 19.68 ms. Median total processing fell from 222.57 to 159.10 ms, 28.5%, and the candidate won every pair. Handler totals include packing and serializing the response. All 24 complete responses matched the deployed hash. This is the smaller candidate to implement first. The map receives the typed PG property names, prior to merging dynamic extras. The proof uses a null-prototype object to retain special property names without object-prototype setters. The production handler should receive the ordinary and packed HTTP regression checks before release.
2. **Send the 90 positional appearance values once per row inside the PG result.** A read-only variation of the genuine SELECT changed only the aggregate for projected appearance rows. Appearance field bytes fell from 8,792,126 to 3,290,716, and total PG field bytes fell from 11,744,517 to 6,243,107. Reconstructing named records produced deep equality for every SQL field and exact final HTTP bytes. The explicit order was verified against migration 003 and its three joined fields. One candidate server plan took 219.82 ms versus 278.97 ms for the measured baseline. The byte reduction is established. A latency gain on the deployed origin remains unmeasured. A production design should list fields by name with a shared decoder and guard schema changes, rather than infer its columns from the first returned row.
